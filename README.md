# Лабораторная работа № 2 — Связные списки

Работа со связным списком: добавление, удаление, поиск элементов.
Дисциплина «Алгоритмы и структуры данных».

## Состав работы

| Файл | Уровень | Что внутри |

| `singly_linked_list.py` | 🥉 Бронза | `Node`, `SinglyLinkedList`: `prepend`, `append`, `find`, `delete`, `get`, `__len__`, `__str__` |
| `doubly_linked_list.py` | 🥈 Серебро | `DNode`, `DoublyLinkedList`: `prepend`, `append` (с `tail`), `find`, `delete`, `delete_node`, `get`, `reverse` |

## Реализация

### Бронза — односвязный список

Узел хранит данные и ссылку на следующий; последний узел ссылается на `None`.

| Операция | Сложность | Как работает |
|----------|-----------|--------------|
| `prepend(data)` | O(1) | новый узел → `next` на старый `head` → `head` на новый узел |
| `append(data)` | O(n) | идём от `head` до конца, прицепляем узел (нет `tail`) |
| `find(data)` | O(n) | идём по ссылкам, сравниваем `data`, возвращаем узел или `None` |
| `delete(data)` | O(n) | ищем предыдущий узел, перекидываем его `next` через удаляемый |
| `get(index)` | O(n) | делаем `index` переходов по ссылкам |

### Серебро — двусвязный список

У узла появляется ссылка `prev`, у списка — `tail`. Это даёт три выигрыша:

* `append` становится O(1) — конец известен, идти до него не нужно;
* удаление **по ссылке** (`delete_node`) становится O(1) — предыдущий узел уже известен,
  искать его не надо (`delete` по значению остаётся O(n) из-за поиска);
* `reverse()` разворачивает список за O(n) — у каждого узла меняются местами `prev` и `next`,
  затем меняются местами `head` и `tail`;
* `get(index)` идёт с того конца, который ближе к индексу: обход сокращается вдвое,
  хотя асимптотика остаётся O(n).

Ключевые тонкости, которые проверяются тестами:

* `__str__` пустого списка возвращает `"None"`;
* при удалении первого или последнего элемента обновляются `head` и `tail`;
* все операции добавления и удаления меняют `_size`;
* после `reverse()` список остаётся связным в обе стороны и с ним можно работать дальше.

### Золото — замеры

`DynamicArray` хранит элементы в блоке фиксированной ёмкости и удваивает её при
переполнении. Сдвиг хвоста при `insert` выполнен присваиванием срезом — это тот же
`memmove` непрерывного блока, что делает настоящий динамический массив на уровне C:
объём работы линеен по числу сдвигаемых элементов.

### Выводы

1. **Вставка в начало.** Список выигрывает, и разрыв растёт вместе с n — значит, дело
   не в константе, а в асимптотике. Списку на вставку нужно создать узел и переставить
   одну ссылку, сколько бы элементов уже ни лежало в списке. Массиву перед записью в
   нулевую ячейку приходится сдвинуть весь хвост вправо, поэтому n вставок дают
   `1 + 2 + ... + n ≈ n²/2` перемещений.

2. **Доступ по индексу.** Массив выигрывает, и здесь разрыв растёт ещё быстрее.
   У массива элементы лежат непрерывно, адрес считается арифметикой по индексу за одно
   действие — время не зависит от n вообще. У списка узлы разбросаны по памяти,
   произвольного доступа нет: до середины надо честно пройти n/2 ссылок.

3. **Общий вывод.** Ни одна структура не лучше другой «вообще» — они меняют одно на
   другое. Список платит доступом по индексу за дешёвые вставки и удаления; массив
   платит вставками в начало за мгновенный доступ по индексу и за компактность в памяти
   (у списка на каждый элемент есть ещё и ссылка). Структура выбирается по тому, какая
   операция в задаче самая частая: часто вставляем и удаляем в начале или по ссылке —
   список; часто читаем по индексу и обходим подряд — массив.

## Сравнительная таблица (домашнее задание)

| Операция | Массив (`DynamicArray`) | Односвязный список | Двусвязный список |
|----------|------------------------|--------------------|-------------------|
| Доступ по индексу | O(1) | O(n) | O(n) |
| Вставка в начало | O(n) | O(1) | O(1) |
| Вставка в конец | O(1) амортиз. | O(n) / O(1)\* | O(1) |
| Удаление (по ссылке) | O(n) | O(n) | O(1) |
| Поиск по значению | O(n) | O(n) | O(n) |
| Использование памяти | n × размер | n × (размер + ссылка) | n × (размер + 2 ссылки) |

\* — O(1), если хранить `tail`.

Пояснения к неочевидным клеткам:

* **Вставка в конец массива — O(1) амортизированно.** Обычно это просто запись в
  свободную ячейку, но изредка ёмкость исчерпывается и происходит перевыделение с
  копированием — O(n). Поскольку ёмкость растёт вдвое, такие перевыделения случаются
  всё реже, и средняя цена одной вставки остаётся постоянной.
* **Удаление по ссылке у односвязного списка — O(n).** Сам узел известен, но чтобы
  перекинуть ссылку, нужен предыдущий узел, а дойти до него можно только от `head`.
  У двусвязного списка предыдущий узел уже есть в `prev`, поэтому O(1).
* **Память.** Массив хранит только сами элементы, но держит запас ёмкости
  (до 2x после удвоения). Список запаса не держит, зато на каждый элемент тратит
  дополнительно одну (или две) ссылки плюс накладные расходы на объект узла.
